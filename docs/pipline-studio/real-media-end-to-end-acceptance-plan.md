# Pipeline Studio 真实媒体端到端验收方案（待评审）

更新时间：2026-09-28

## 1. 本次要证明什么

用一个**单镜头就是完整作品**的短视频，实际走通：用户脚本目标 → 四个内部 Specialist → Canvas Plan → 可运行视频节点 → 用户手动启动真实视频生成 → Provider Job → 本地 Artifact → 播放与交付文件。视频须有完整起承转合，不能只是用一个测试画面冒充成片。

本次不实现或测试多镜头拼接。当前 `assembly` 仍为 `coming soon`；多镜头短剧即使全部镜头视频生成成功，也只能判定“素材生产链路通过”，不能判定“最终成片交付通过”。[成片合成 V1 设计](./assembly-v1-design.md) 保留，后续独立实施。

## 2. 固定验收样例

建议制作一条 5–10 秒、9:16 的无对白单镜头微短片：雨夜外卖员把自己的雨披盖给纸箱里的小猫，收尾停在小猫抬头与外卖员离开的完整动作上。要求明确一个角色、一个场景、一个连续动作、一个情绪收束。最终时长以**验收时已启用 Route 的 Schema**为准，不强行写死模型不支持的值。

验收开始前固定并记录输入文本、模型配置、Route ID 与版本、目标画幅/时长、项目目录和代码提交。若当前 Route 无法直接文生视频，则使用该 Route 所需的最小参考图链路，并把额外生成次数与费用单独记录；不为了让结果通过而临时更换样例目标。

使用隔离 Pipeline 项目；不把测试产物混入用户真实项目。只启动一条目标视频 Generation Run。若模型输出了多个镜头，记录为“单镜头约束未满足”，不从中挑一条成功视频替代端到端通过。

## 3. 执行步骤与证据

| 步骤 | 操作 | 必须留存的证据 |
| --- | --- | --- |
| A. 创作准备 | 在 Pipeline Chat 输入固定目标，实际调用 Script、Asset、Storyboard、Prompt Specialist 并应用 Plan | Session ID、各 Specialist Profile 版本与执行模式、Plan ID、画布 revision、节点和连线快照 |
| B. 生成前检查 | 核对一条 Shot Spec 与目标视频节点，执行 `canvas_prepare_generation` | 一镜头、正确目标时长和 9:16、真实启用 Route、Prompt/参数/引用、无阻塞错误 |
| C. 真实生成 | 用户在画布显式启动该视频节点 | Generation Run ID、Provider Job 状态变化、提交/轮询/下载结果；不记录凭据 |
| D. 本地产物 | 等待 Run 成功并选定其视频 Artifact | Artifact ID、工作区内本地路径、大小、MIME 类型和文件指纹；通过受保护媒体接口读取 |
| E. 成片检查 | 在应用内播放完整视频，并用 ffprobe 检查文件 | 可解码的视频流、实际时长/宽高/帧率/音轨、首尾画面和叙事完整性、人工观看结论 |
| F. 恢复检查 | 刷新或重启应用，重新打开项目、节点历史和已选产物 | Run、Job、Artifact、选片与本地文件仍可定位；不重新提交付费任务 |

人工观看采用明确结论：主体和动作可辨、镜头包含目标开端与收束、无明显黑帧或截断、画幅正确，声音若 Route 承诺音频则检查音轨及可听性。生成质量可能受模型波动影响；若技术链路成功但画面不满足创作目标，分别记录“技术链路通过、内容质量未通过”，不可合并为全流程通过。

## 4. 判定规则

**通过**同时要求：

1. 固定目标经四个 Specialist 形成一条可编辑、可预检的单镜头视频链路；Agent 没有自动创建付费 Run。
2. 用户显式启动后，仅有预期的真实 Generation Run；Provider Job 成功，本地视频 Artifact 已持久化；没有重复付费提交。
3. 产物能在应用内完整播放，受保护接口能重新读取本地字节，应用重启后仍可找到；ffprobe 与人工观看均符合固定目标。
4. 验收报告保留原始失败、重试和费用事实，不通过手工替换视频文件或修改数据库补造成功。

若供应商失败、下载失败或内容质量失败，记录失败阶段和可恢复动作。可以针对同一目标进行一次有记录的重试，但第一次失败仍保留在报告里；重试可能再次计费时必须明确区分重新提交与仅重新下载。不能因为重试成功就把首次成功率记为 100%。

**本次不声称**多镜头自动合成、按集导出或“任意短剧一键成片”通过。当前 20 条 Specialist 固定评测只验收到画布准备，而且 V1.1 最近一次正式评测未通过；这次真实媒体验收不能替代该质量门槛。

## 5. 执行顺序

1. 先核对当前配置中可用的文生视频 Route、凭据存在状态和本地 FFmpeg/ffprobe；只读取凭据是否存在，不输出 Key。
2. 准备隔离项目与固定样例，执行 A、B。若单镜头约束或预检失败，先记录并修复准备链路，不启动付费生成。
3. 由用户在画布显式启动 C，跟踪持久化 Run 至终态。此前会话已授权付费 API；真正执行验收时无需再次请求相同授权。
4. 完成 D–F，形成包含实际 ID、截图/媒体元数据、费用或提交次数、失败和人工观看结论的验收记录。只有真实产物可读且观看通过才标记本次单镜头成片验收通过。

浏览器只用于 B 的交互确认和 E/F 的播放、刷新与选片检查；状态排查优先使用 Run/Artifact API 和本地文件证据，不反复盲测 UI。
